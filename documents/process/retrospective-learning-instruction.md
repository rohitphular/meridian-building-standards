# Retrospective Learning Instructions

Read the retrospective conclusion and save the process lessons to memory. This ensures the lessons carry forward into future epics without relying on re-reading old conclusions.

---

## What to Save

Save a memory for each action item or process rule that applies to your role. Do not save:
- Technical details (formulas, field names, model parameters)
- The other party's action items
- Observations with no concrete rule attached

For each memory, use type `feedback` and follow this structure:

```
---
name: [short-kebab-case-slug]
description: [one line — what this rule is about]
metadata:
  type: feedback
---

[The rule, stated as a forward commitment.]

**Why:** [The specific incident from the retrospective that caused this rule.]

**How to apply:** [When does this fire? What do you do differently?]
```

---

## Rules

- Save each memory as a separate file in your memory directory.
- Add a pointer to each new memory file in `MEMORY.md`.
- If a new rule updates or replaces an existing memory, update that memory rather than creating a duplicate.
- Do not save observations — only rules that change future behaviour.
